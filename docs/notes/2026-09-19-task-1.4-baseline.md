## Capacity decision: 512 does NOT fit — open map-resize/epoch follow-up

System admission is stable 4/4 runs: p11-kit (64 tables → 410 slots,
spill 60) + one SoftHSM view (68) = **478/512 allocated (93.4%)**,
34 free; whole-module refusals at occupancy 478: p11-kit-trust (+68),
second SoftHSM view (+68), snap p11-kit 0.4.4 (+92), firefox
libsoftokn3 (+68). Honest capture-wide union: **478 + 68 + 68 + 92 +
68 = 774 > 512**. Allocated-vs-active 478/478 (no churn; retention
verified in code — slots vec grows, indices never reused). First
exhausted dimension: **slots** (bytes/work/semantic unexhausted; all
other counters zero).

Worse than the arithmetic: the refused host SoftHSM view is the
*active workload provider* — K=4 spends 410 slots on dormant p11-kit
templates and refuses the calling provider, so system coverage is
0/20002 where the pre-1.2 tree (p11-kit refused whole) observed full
counts. K=4 bounds resources but, without publication/activity
ordering, inverts coverage priority — the quantified input to 1.5/1.6.

Decision: keep 512 + honest refusal for Phase 1; open the follow-up
sized AFTER 1.6 (broad attach implies 6530-class demand for one
p11-kit; a blind resize to 774 covers today's desktop only). The
follow-up should also record refused (dev,ino): refusals currently
carry name+reason only, so the audit above is inference, not evidence.
