# p11scope v0.7.1

## [0.7.1] - 2026-11-17

v0.7.1 catches short-lived programs from their first call, counts
providers linked into a program, and quiets exit-time noise.

What's new (one line each):

- Getter-only manifests: providers statically linked into a program count through their getter returns (`scripts/getter-manifest.py` writes the manifest).
- `run` observes short-lived descendants from their first call via the pause chain (pkcs11-check smoke recall 1.0, was 0.81).
- Reports name each module's first complete attach instant (`first_attached_at_ns`, additive).
- Unknown function rows say why (`unnamed_reasons`: `heuristic_table`, `selection_without_standard_proof`).
- Skipped discovery views explain their retries (`discovery_retry_classes` per-class breakdown).
- Late providers attach at thousands of endpoints (bounded shared handle table; manifest scale shedding fixed).
- Per-key tracking survives transient audit refusals (up to 32 per rolling 2 minutes) and degraded claim/certify cases instead of stopping.
- Exited-but-unreaped processes, pre-existing kernel-thread exits and proven mid-scan exits no longer file phantom gaps.
- Large providers are examined through bounded windows instead of a fixed size gate; starved brackets keep decoded modules.
- `--module` matches every recorded path and tolerates ` (deleted)`; unmatched inputs are named while the capture still exits 0.
- Per-key rows survive provider load/unload churn; slot reuse keys on exact file identity.
- The coverage line counts distinct files once; the pre-arm witness no longer freezes exits as Pending.
- `run` finishes arming before the `capturing:` line, so waiting children count from their first call.
- Stub-pool manifests record the first-mint v3 slots, so first getter calls attach.
- Cgroup passes reuse unchanged file facts; attach work continues between passes.
- `doctor` recognizes Podman, names setcap/container grants, and explains `-o` ownership needs.
- `--output-owner UID[:GID]` hands `-o` reports to a container bind-mount owner.
- Quieter default stderr (routine cleanup receipt gone; `-v` restores), grouped proxy refusals, `-v` memory lines.
- Pre-6.8 overlayfs scans no longer split staged providers (6.6 exact-accounting failures fixed).

Known issues ([details](../known-limitations.md#known-limitations-in-070)):

- [getter-only manifests](../known-limitations.md#getter-only-manifests-count-tables-read-at-run-time) stay `PARTIAL` with names not layout-proved.
- [key operations can still stop partway](../known-limitations.md#key-operations-can-still-stop-recording-partway-through-a-long-system-wide-capture) on a busy host (narrower since 0.7.1).
- [`run` member stops](../known-limitations.md#one-shot-tools-under---system-first-use-missed-later-runs-caught) can surface one `EINTR`; the watchdog resumes stopped members.
- Unproven mid-scan exits still file skips on a busy host (call counts stay exact).
- [mid-load replace windows](../known-limitations.md#a-mid-load-plan-rebuild-can-lose-first-calls-in-its-replace-window) can lose first calls without a gap row.
- [`run` with many short-lived children](../known-limitations.md#run-with-many-short-lived-children-can-rarely-miss-seconds-of-calls) can rarely miss seconds of calls.
- [stub-pool manifests cover one getter-call order](../known-limitations.md#stub-pool-provider-manifests-cover-one-getter-call-order).
- The [v0.7.0 limits](../known-limitations.md#known-limitations-in-070) not fixed above still apply.

Upgrade notes:

- Drop-in: same install steps and commands.
- Default stderr is quieter (the routine cleanup receipt is gone); `-v` restores every line.
- `doctor` prints new rows (Podman, loader N/A, ownership grants).
- New JSON keys are additive only; no schema revision.
