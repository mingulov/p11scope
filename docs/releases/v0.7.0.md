## [0.7.0] - UNRELEASED

v0.7.0 shows which application called the token, fixes system-wide
binding, and ships a container image.

What's new (one line each):

- App labels: `python3 [backup.py]`, `java [app.jar]` name the app behind the runtime.
- Launcher chain: callers show `from backup.sh` (one hop; full chain in verbose and JSON output).
- `inventory --system` now binds usage on large hosts (was: zero rows).
- Deferred admission refusals settle once the endpoint is admitted (was: up to 2 stayed refused).
- Observer memory stays flat under process churn (was: grew toward ~1 GB/hour on a busy host).
- stdout/stderr keep working under sudo with tighter capabilities.
- Container copy-ups attribute both file versions, so calls on either side count.
- Tested against OpenSSL, p11-kit, pkcs11-tool and GnuTLS clients.
- Container image `ghcr.io/mingulov/p11scope:0.7.0` for Docker and Kubernetes.
- Exact totals when many threads share one provider (rows may stay partial, see known issues).
- Tested on Linux 7.4-rc1, plus the 6.6–7.3 matrix.
- Cost: overhead is visible, and it works well at 5,000 calls/s on a VM with limited resources.
- `run` hands your program back instead of killing it: a stopped run, a spent event budget or a capture error leaves the child running.
- Every run that collected data writes its report, even when refused, stopped or interrupted.
- Captures degrade honestly instead of showing empty views: a scan report where live capture is unavailable, partial results when stopped early.
- `inventory --event-log -` streams live events to stdout for container log collectors, with optional periodic totals.
- Docs pack: [troubleshooting](../troubleshooting.md), real first-run output, [why not just pkcs11-spy?](../overview.md#why-not-just-pkcs11-spy), [tested targets](../overview.md#tested-providers-and-applications).
- Attach slots: 2,112 per capture (was 512), retired slots are reused once final, and oversized providers attach in part with a named gap.
