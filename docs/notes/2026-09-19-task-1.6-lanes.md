# Task 1.6 lanes: coverage architecture on measurement (2026-09-19)

Decision experiment: broad attachment (every validated fixed-family
target probed up front) vs publication-selected (K=4 window + live
publication), plus the storage half (dense array vs bounded sparse
map). No BPF ABI change; all lane code is userspace-only and
experiment-gated (`P11SCOPE_BROAD_ADMIT=1`, default off).

## Lane A: attach-cost isolation (owned fixture)

Protocol: stage children publish wrappers BEFORE capture (unobserved),
the observer attaches scan-only, then a gated `C` call plan activates
the dormant wrappers mid-capture. Single topology keeps
{0(fwd ords 5,43), 4, 5(fail ord 43), 7, 13, 17} (dormant activation,
sparse indices, 6 wrappers, direct forwarding, wrapper-only failure,
nested wrapper→backend); pair topology (one cgroup, one inode) keeps
{0,1} + {5,6} (sparse indices across processes). n=10 per
(idx, ordinal); 6 cells, all `counts_match=True`, all loss counters
zero, verdict PARTIAL (count-only, honest terminal).

Loaded box (load ~3-4/12, no sibling builds): counts are load-proof,
timings indicative. Multi-attach unsupported on this tree (spike only,
`crates/bpf-multi` unwired) — singles everywhere.

Findings:

- Coverage: broad observes every dormant wrapper's FIRST call
  (gap=0; 340 wrapper calls incl. 10 rv48 fail-only, exact per
  ordinal for named idx0 + exact unknown total; 34/387 slots active,
  353 dormant attached and silent). Selected misses exactly the
  beyond-K=4 indices (300/120), everything admitted exact.
- Invariants hold under broad: 387 functions rows = 387 physical
  targets (distinct identity, never merged — `unknown` is a label,
  not a slot); pending_returns 0 + in_flight 0 (exact pairing);
  per-target rows kept with rollup after (exact kept).
- Attach cost is ~flat: +0.1–0.2s for 14× probes (fixed BPF-load
  costs dominate; per-probe marginal ≈0.2ms).
- Detach is the broad tax: ~38s vs ~3s, linear at ~20 probes/s
  (3 broad samples: 38.57/37.65/38.93; cross-validates 1.4's
  16–18/s system rate). At p11-kit scale (6530 targets) that
  projects to ~5.5 minutes — broad needs the detach problem
  (or Phase 2 multi) addressed alongside capacity.
- Target CPU 0.0s both lanes (360 gated calls below tick noise);
  map memory IDENTICAL both lanes (9,168,880B — dense maps are
  occupancy-independent); STATS full dump 0.27–0.28s both lanes.
- Pre-capture forwarding gap (both lanes, by design): forwarded
  ordinals (backend-direct, 20 calls) unobservable — backend.so is
  unprobed and no live publication exists. Quantified, not hidden.
- Method note: closing targets early ends a per-PID capture before
  --duration (observed once, 15s→5.8s); the driver holds stages
  open, giving a dormant tail with zero spurious records.

## A2: real-p11-kit admission (no BPF)

Broad file-backed is infeasible at dense-512 for one real provider.
Publication-selected covers 410 slots honestly where broad covers 0.

## Lane B: storage (dense vs bounded sparse, modeled)

Anchors (measured memlock @12cpu): STATS 1,823,024 (512×296×12
+ slack); START hash 6,034,528; RV percpu-hash 754,560
(→ ~72B/entry hash overhead, measured not assumed).

STATS bytes, dense array (fixed by slots) vs NO_PREALLOC percpu
hash C=8192 keyed by physical target (by residency):

| shape | dense @12 | dense @64 | sparse @12 | sparse @64 |
|---|---|---|---|---|
| 512 / resident 512 | 1.82M | 9.70M | 1.93M | 9.81M |
| 6530 / resident 6530 | 23.19M | 123.70M | 23.83M | 124.34M |
| resident 34 (fixture) | — | — | 0.19M | 0.71M |
| resident 0 (dormant) | — | — | 0.07M | 0.07M |

Sparse wins iff residency << slots (fixture 34: 9× smaller than
dense-512; dormant: 64KB buckets vs 1.8MB). At FULL occupancy sparse
≈ dense + ~3% — no free lunch; the win is removing the ceiling and
not paying for dormant providers, not beating dense per byte.

Protocol (validated in `scripts/task-1.6-lane-b-sparse-model.py`,
self-test 7/7): lookup → alloc+init with NOEXIST → EEXIST relookup
→ update; full map refuses with counted failure evidence (never
evicts, never merges). Pinned: exactly-once alloc + lossless updates
under 8-thread race, deterministic race injection, full/partial
replay (C=512 loses 6018/6530 under a full sweep — counted).

Capacity design for the follow-up (covers every per-target map):

- STATS: dense Array[512] → sparse percpu-hash C=8192 keyed
  (dev, ino, file_offset). Covers 6530 + headroom.
- RV_COUNTS: C=4096 → C=16384 keyed (target, rv). MUST grow
  (4096 < 6530 targets).
- START: keep C=16384 (in-flight bound), rekey
  (pid_tgid, slot) → (pid_tgid, target); key 16→24B, ~same bytes.
- DESCRIPTORS: unchanged (function-indexed [105], slot-independent).
- Queues (EVENTS/DISCOVERY rings): unchanged (rate-driven, and
  broad adds sources, not call rate).
- Identities (task-storage cookies/owners): unchanged (per-task).
- Failure evidence: new EVIDENCE cell for STATS alloc failures;
  the pattern exists (START/RV insert failures already counted).

## Decision (from the numbers)

The brief's leading hypothesis is CONFIRMED with sequencing —
composition: broad file-backed + publication-driven heap/forwarded.

1. NOW (dense 512): publication-selected stays. It covers 410
   slots of real p11-kit honestly; broad refuses whole (0).
   Broad-when-fits-then-selected-fallback strictly dominates on
   paper but needs a cross-module budget-ordering analysis first
   (a lookalike-rich early module could starve later providers) —
   follow-up, not this task.
2. NEXT (BPF ABI follow-up, contingent — now triggered): the
   Lane-B sparse redesign (C=8192 STATS/RV) + a detach fix (or
   Phase 2 multi, which composes: fewer links, faster detach).
3. THEN: enable broad admission (this experiment's merge
   semantic). The fixture pool adapter stays experiment-only;
   production needs per-provider recognized-layout recipes
   (p11-kit build-id + layout first). Unknown layouts stay
   publication-driven — the measured composition boundary
   (stripped variant: broad adds nothing, exactly).
