# v0.8.0 Key Metadata Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship inferred key family, size class, and source-carrying creation facts on per-key rows.

**Architecture:** Port the R2 creation-template path with per-field source (v6); add S-cell/V-scalar length adapters on 9 new + 2 extended object descriptors with a wire v2 tail; join completion lengths to operation identity in userspace (no `AggKey` dimension, no `metadata_at_use` rewrite); publish closed v7 row keys with concise text and `-v` detail.

**Tech Stack:** Rust (edition 2024, release toolchain `.release-rust-version`), existing object-capture adapters; no new crates, no new maps.

**Spec:** `docs/superpowers/specs/2026-11-14-v080-keymeta-design.md`
(round 1: K1–K6 decided as recommended unless review rules otherwise;
schema version allocation is the integrator's — Task 3 re-points if
keyrows claims a version first).

## Global Constraints

- Never capture PINs/keys/payloads/env; `docs/privacy/allowlist-v1.md` byte-identical.
- Missing observations stay unknown with named reasons; refusals, loss and PARTIAL coverage reported honestly.
- No BPF change before the §11 amendment text passes owner/Opus privacy review + Codex re-review (still PROPOSED until then).
- `metadata_at_use` stays established-only and frozen at Init receipt; no-backfill pins re-run green.
- Profile, trace and metrics never carry object facts; observed-profile v2/v3 untouched.
- Schema section versions: v6 = R2 + per-field source, v7 = inferred keys; older versions frozen and byte-stable.
- Concise CLI default; inferred facts parenthetical only where they add information; `-v`/JSON carry detail.
- Cargo only via `mise exec -- ./scripts/cargo.sh`; TMPDIR on disk, umask 022.
- Tests-first: RED run saved outside tracked files, then GREEN; every new check non-vacuous.

## Review Focus

- A length cell aliasing payload bytes must refuse via span guards, never publish a payload-derived class — pinned by overlap/alias twins in Task 2.
- A 2041-bit RSA key (256-byte signature) must show "RSA 2048-bit class", never `rsa_2048` — pinned by the 2041 control in Task 3.
- A key used under two mechanism families must show `conflicting` with both sides, never first-wins — pinned by conflict twins in Task 3.
- Inferred facts must never reach CBOM `related-crypto-material` established fields — pinned by a CBOM exclusion twin in Task 3.
- A provider with NULL `C_SignRecover` must still admit no-manifest key operations (length entries per-entry optional) — pinned by an authority twin in Task 2.
