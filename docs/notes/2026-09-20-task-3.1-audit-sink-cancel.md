## What changed (behavior)

- F4, `src/sink.rs`: the tick budget (250ms) is now drawn in ≤25ms poll
  slices (`SINK_POLL_SLICE`); cancellation is consulted on every
  interruption and between slices. A pending cancel sheds promptly:
  nonblocking writes take available room, the rest drops with the
  standard counters (`timeouts`, `dropped_bytes`, `stall_ms`). No new
  counters, no schema change; unwatched flushes keep legacy behavior.
- F4, `src/run.rs`: `SignalState` carries a shared cancel flag raised
  with the first observed stop signal; both capture loops hand it to
  their stdout sink.
- F3, `src/run.rs` trace terminal: flush pre-terminal bytes *before*
  snapshotting; emit COUNT + pre-flush EVIDENCE to stdout through the
  shared emitter; flush the terminal records on a fresh tick budget;
  then finalize the `-o` file's EVIDENCE record *after* that flush with
  the refreshed accumulator total plus a fixpoint over the record's own
  length delta (`resolve_terminal_sink_total`). The stdout copy is
  best-effort (a record cannot report its own delivery fate); both
  copies are identical when lossless. Profile terminal already
  refreshed after its flush; unchanged.

Mechanism note: the audit's EINTR-retry description was right for
production too — empirically the poll returns EINTR on signal delivery
(even with registry-identical SA_RESTART|SA_SIGINFO handlers: 0.15ms
abort, 4/4 runs), and the old code retried without consulting
cancellation. The slice bound is the deterministic backstop for any
restart/delivery edge. The observer is single-threaded at flush time
(`threads_max=1` in the rerun records).

## Residual concerns

1. stderr stall notes stay per-throttled-window (`dropped N bytes in M
   flush timeouts` covers the collection window, ~5s throttle); only
   EVIDENCE carries exact totals. Pre-existing display shape, kept.
2. Bytes never offered to the sink (after a broken pipe closes stdout)
   are still uncounted, mid-capture and terminal alike — the F3
   byte-exactness covers sink drops on a draining reader, which is the
   audit's comparison. Counting never-attempted bytes would need the
   accumulator threaded through every `write_stdout` call site.
3. The adapted watcher threshold (≥20ms) tracks the new poll shape; the
   frozen audit watcher (≥100ms) cannot fire on the fixed binary by
   design. The production oracle (`cancel_probe_verdict`) is
   implementation-agnostic and is the binding gate.
4. Full-oracle load flakes (proven environmental, not this change):
   five timing-sensitive Python/subprocess suites (`metadata_canary`,
   `lane13_…`, recorded-launcher, `dual_build_callers`,
   `ia32_lifecycle`) fail under parallel load with deadline/timeout
   signatures (0.2s reader timeout, 12s self-test timeout, launch
   deadlines). None executes the observer binary or any changed
   lib path (integration tests cannot reach `pub(crate)`/private
   items); `metadata_canary` passed then failed on the identical
   binary; `dual`/`ia32`/`lane13` pass alone; `recorded_launcher`
   fails identically on the unmodified base `5cad00c` with
   *different* subtests failing run to run. Observed box load during
   failures: 9–31 (1m avg), incl. a sibling 6-core test burn. One
   *real* contract break (capture-loop wiring guard) was found and
   fixed by routing stdout emission through the shared emitter. The
   final full run above is the binding evidence.
