# Task 3.1 audit-oracle fixes (F2 must; F6/F9 opportunistic)

Branch `task-3.1/audit-oracle` from repair tip `5cad00c`. Fixes three
oracle defects from the 2026-09-20 system-scale adversarial audit
(`audit-system-scale-2026-09-20/AUDIT.md`, read-only, untouched).
Before/after verdicts below replay the audit's immutable PoC shapes.

## F2 — system coverage requires owned attribution (P1, must)

`scripts/system-scope-measure.py` accepted system scan-only coverage when
the sum of ALL unknown-name calls covered the owned TRUTH total, and
`assess_window` then marked the window valid — foreign traffic certified
a refused owned workload.

Fix: coverage on system scope now requires the owned workload module
(resolved from `workload_argv` against admitted `evidence.discovery`)
to be admitted, and scan-only coverage additionally requires
owned-attributed calls (exact `dev/ino/sha256` identity, path fallback
for synthetic shapes) to cover truth. Null-module (ambiguous/
unresolved) and foreign-attributed calls never count toward owned
coverage. The trace-system aggregate rule gets the same admission gate;
pid-exact rules are unchanged (no foreign traffic there). The window
carries the explicit coverage note via a new optional
`assess_window(coverage_detail=...)` parameter, and the record's
limitations text now states the attribution rule.

Before (audit PoC shape: owned refused, 7 foreign unknown calls, TRUTH=7):

```text
verdict=PARTIAL counts_match=True wall=12.0s
"window_valid": true
"window_note": "window valid (strong gate frame; system covering totals)"
"match_note": "system scan-only: names unavailable (unknown); total coverage 7 >= 7"
```

After:

```text
verdict=PARTIAL counts_match=False wall=12.0s
"window_valid": false
"window_note": "window INVALID (...): counts_match=False (system scan-only:
  names unavailable (unknown); owned workload module ['controlled-owned.so']
  not admitted (admitted: ['foreign.so']; refused: ['owned.so']);
  total coverage unprovable)"
```

`PARTIAL` and the refusal stay visible; only the false coverage
certification is gone. Honest G1-style zeros still fail (pinned by test).

## F6 — proxy lane requires per-provider call presence (P2)

`validate_proxy_capacity_fallback` only required global `called > 0`, so
complete proxy-call loss passed with one SoftHSM call left.

Fix: the lane now requires `called_soft > 0` AND `called_proxy > 0`
(each provider handled at least one call), matching what a green lane
claims (two-provider call coverage). The audit's mutation is now a
self-test mutation in both directions (all proxy calls zeroed; the one
SoftHSM call zeroed).

Before: `MUTATION all proxy calls lost; only one SoftHSM call left: ACCEPTED`
After: `MUTATION ...: REJECTED: the proxy handled no calls: complete
proxy-call loss is not two-provider coverage` (control still ACCEPTED).

## F9 — detach tail prefers the in-observer timer (P3)

`derive_phases` assumed requested duration = measured capture and could
report `detach_s=0.0` while the observer's own timer measured a real
tail (F1 `repair-burst-load24`: `detach_s=0.0` vs
`phase_ms.detach=11826`).

Fix (small): `derive_phases` takes an optional `phase_ms`
(`evidence.scheduling.phase_ms`, plumbed through in `main()`). When the
fd-trace estimate is 0.0 and the in-observer detach timer shows a real
tail, the timer value is used with a method warning; an estimated 0.0
with no timer gets an explicit unconfirmed-estimate warning; an
observer-confirmed 0.0 stays silent; genuine nonzero tapers are
untouched. `task-1.6-lane-a.py` (positional caller) is unaffected.

On the F1 shape (synthetic fd trace + `phase_ms.detach=11826`):

```text
before: detach_s=0.0, warnings=[..., "detach start fell back to first post-expiry dip", ...]
after:  detach_s=11.826, warnings=[..., "fd-trace detach estimate 0.0s contradicts
  the in-observer detach timer (11.826s); using the in-observer value"]
```

  process emitting the workload's exact names could inflate it); only
  the admission gate was added there.

  `drain_s` keeps the fd estimate; no in-observer capture timer exists

- Trace-system coverage with owned admitted still uses the unattributed
  kernel aggregate (documented window proof, not per-call proof).
