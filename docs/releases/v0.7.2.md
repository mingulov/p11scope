# p11scope v0.7.2

## [0.7.2] - 2026-11-22

v0.7.2 names the keys behind the calls: per-key rows carry inferred
families, opt-in sizes and creation-template curves, including
post-quantum use, while exited callers fold into exact aggregates
and late providers attach promptly under churn.

What's new (one line each):

- Inferred key families on `--key-operations` rows, from operation mechanisms in both modes (`probably RSA (from mechanism)`).
- Opt-in key sizes via `--key-sizes` (`RSA 2048 (from signature length)`; needs `--key-operations`, off by default).
- Creation-template curves and parameter sets for new keys (new-site metadata, HKDF/Edwards/Montgomery without a query).
- Standard ML-KEM/ML-DSA operations infer their family (PQC-capable providers such as kryoptic); ML-KEM sets size from ciphertext lengths.
- Firefox post-quantum TLS key exchange shows by number and by name (NSS vendor ML-KEM ids; ML-KEM-768 from a 1088-octet ciphertext).
- `--provider-info` opt-in: provider, token and mechanism facts on inventory runs (FULL build, `--capture auto`/`native`).
- Captures that kept per-key rows but lost the live feed (a brief Firefox run) report `partial` with retained rows instead of `unavailable`.
- Unknown-key rows keep by-number mechanism counts (up to 8 per row, further ids refused into a named gap).
- Proven-exited callers fold into per-module `departed_use` aggregates with exact counts (JSON consumers: read `departed_use` too).
- Late providers attach promptly under churn (501/501 and 1001/1001 newcomers admitted, 0 rejected; 0 of 309,861 joined calls before).
- High-rate key operations lose no records to the reservation table (13.8–19.1% loss at 5,000 calls/s removed; the 4096 bound is unchanged).
- Retired counting coverage is disclosed (`coverage_retired` windows, `coverage_retired_slots`); run-tree retires attribute to their member.
- A run's repeated gaps fold into counted aggregates, so gap volume stays flat on long captures.
- `-o` reports survive destination I/O failures (per-user recovery dir, one stderr line naming the saved path).
- Counter-bank return losses count per item and the RV table reads as a lower bound when exhausted.
- A capture under a flood of short-lived processes no longer stops counting partway (the v0.7.1 newcomer-flood regression).

Known issues ([details](../known-limitations.md#known-limitations-in-070)):

- Firefox RSA client-certificate rows can be lost (fix planned for 0.8.0).
- [Low per-key coverage on busy hosts after an audit void](../known-limitations.md#key-operations-can-still-stop-recording-partway-through-a-long-system-wide-capture) (re-entry planned for 0.8.x).
- [Inventory memory still grows slowly with process churn](../known-limitations.md#observer-memory-grows-under-heavy-process-churn) (about 3 MiB/h; a bound on the remainder is planned for 0.8.0).
- [Getter-only manifests](../known-limitations.md#getter-only-manifests-count-tables-read-at-run-time) stay `PARTIAL` with names not layout-proved.
- [`run` member stops](../known-limitations.md#one-shot-tools-under---system-first-use-missed-later-runs-caught) can surface one `EINTR`; the watchdog resumes stopped members.
- [Mid-load replace windows](../known-limitations.md#a-mid-load-plan-rebuild-can-lose-first-calls-in-its-replace-window) can lose first calls without a gap row.
- [`run` with many short-lived children](../known-limitations.md#run-with-many-short-lived-children-can-rarely-miss-seconds-of-calls) can rarely miss seconds of calls.
- [Stub-pool manifests cover one getter-call order](../known-limitations.md#stub-pool-provider-manifests-cover-one-getter-call-order).
- The [v0.7.0 limits](../known-limitations.md#known-limitations-in-070) not fixed above still apply.

Upgrade notes:

- Drop-in: same install steps and commands.
- `--key-sizes` needs `--key-operations`; sizes stay unknown without it and no length word is acquired.
- JSON consumers: exited callers leave `callers[]`/`edges[]`/`instances[]` for `departed_use` once rendered; the event stream keys are a superset of the snapshot. New `budgets` counters account the fold.
- Object observations ship section versions 6–9 (new-site metadata, inferred families/sizes, provider info, NSS PQC); versions 1–5 stay frozen. Consumers dispatch on the exact version.
- New text rows: `departed use:` summaries, provider lines with `--provider-info`, `coverage_retired` windows.
