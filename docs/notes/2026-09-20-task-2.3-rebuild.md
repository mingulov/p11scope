# Task 2.3: group-rebuild equivalence measurements (singles vs multi)

**Date:** 2026-09-20 · **Branch:** `task-2.3/group-rebuild` · **Rev:** `2c2d321`
**Kernel:** `7.0.0-31-generic` (x86_64) · **Toolchain:** Rust 1.88 (release build)
**Cell:** `/var/tmp/p11scope-ws-tmp/task-2.3-lane` (0700 lane scratch, kept out
of the repo per scratch rules: `provider-b.c`, `driver.c`, `lane.py`,
`check23.py`; provider A is the committed
`tests/fixtures/live-discovery-provider.c` built exported)

## Method

Aliasing-downgrade trigger: provider A (104 file-backed table slots,
`--manifest` attested so its slots carry canonical descriptors) is loaded
before capture; mid-capture the driver dlopens provider B, whose full
104-entry table aliases A's `C_Sign` slot (entry 43, same address via
`DT_NEEDED`, asserted `B[43]==A[43]` in-driver). Live discovery extends
the plan — a replace delta downgrades the shared slot to `COUNT_ONLY` —
so `detach_slots` must retire one member of A's live multi group: the
explicit group rebuild. Singles runs the same flow per-slot (no rebuild).

A poison-offset trigger was considered first and rejected by measurement:
a privileged spike over `link_create` on this kernel showed entry and
return validate offsets identically (only absurd offsets such as
`0xffffffff` refuse with `EINVAL` on both sides), so fresh attach cannot
produce an entry-partial member — the realistic rebuild trigger is
retire/replace of a group subset, which this lane drives deterministically.

Driver (`driver.c`, fifo-gated like the 2.2 lane): READY → observer
attaches (10 s) → GO → phase 1 (20 calls each to A[0], A[1], A[43]) →
dlopen B → 15 s quiet settle (the rebuild window) → phase 2 (20 calls
each to A[0], A[1], A[43], B[2], B[4]) → DONE + `expected.txt` ground
truth (160 calls: `C_Initialize`/`C_Finalize`/`C_Sign` 40 each,
`C_GetInfo`/`C_GetSlotList` as `unknown` 20 each — B is scan-only
unlinked, so the 1.3 mislabel guard names its slots `unknown`). B has no
constructor and the driver reads its table through the non-hooked
`P11ScopeBTable` export, so no bootstrap handout calls pollute the truth.

Observer: `p11scope profile --pid <drv> --manifest manifest-a.json
--duration 90 --mode <profile|metrics> --attach-backend <multi|singles>
-o <lane>.json`, privileged. Checker (`check23.py`, `/tmp`-side): oracle
schema validation (`exact_metrics_schema`, profile-v3 mechanisms/gap
rules imported from `scripts/check-capture-evidence.py`), exact per-name
`functions[]` counts vs ground truth, every loss counter zero,
`C_Sign` observed through a module-ambiguous slot (the downgrade proof),
`multi_rebuild_gaps >= 1` on multi / `== 0` on singles, then exact
cross-backend count equality.

## Headline

- **Equivalence:** multi (with one live group rebuild per profile leg)
  reports exactly the singles-baseline counts on all five legs — 160/160
  ground-truth calls, no duplication, no drops. The rebuild neither loses
  survivor observations (phase gating keeps calls out of the window) nor
  double-counts the replaced slot (40/40 `C_Sign` across the descriptor
  generations).
- **Gap publication:** `multi_rebuild_gaps` 1 on both multi profile legs,
  0 on singles; verdict PARTIAL on every leg (gaps on multi,
  module-ambiguous `C_Sign` slot on both), per the oracle PARTIAL rule.
- **Trigger proof:** `C_Sign` carries `module_ambiguous: true` on every
  leg — the second claimant forced the descriptor downgrade that made
  `detach_slots` rebuild.
- **No stale-start fallout:** `start_insert_failures` and
  `unmatched_returns` are 0 on every leg — post-rebuild calls paired
  fresh, as designed (returns consume the one stale start each at most).

Timing (observed, noisy box — no claim): terminal `detach` phase
~55 ms multi vs ~10 s singles at 418 endpoints (the known per-link
singles taper); `discovery` phase ~0.5–0.6 s multi vs ~10.5 s singles
(live reattach churn). Box load was shared with sibling workers
throughout; counts and gap fields are exact, wall times approximate.
