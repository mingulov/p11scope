# v0.8.0 Key Metadata Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship inferred key family (default-on), size class from operation lengths (opt-in `--key-sizes`, off by default per owner 08:50), and source-carrying creation facts (default-on) on per-key rows, plus provider/token/mechanism info (Task 7, default-on).

**Architecture:** Port the R2 creation-template path with per-field source (v6); add S-cell/V-scalar length evidence as evidence-only trailers on the journal END form in extra journal-object programs (flag-gated, §8.6) and info evidence in the inventory info pair in every native inventory mode (default-on, §17.4) — separate `EVIDENCE_POSITIONS` table, `object_descriptor()` untouched, journal classification/census/sole-complete/alias agreement byte-identical, +0 endpoints for length (Singles +0/+0 links, Multi +G/+G per §8.3; info per-backend per §17.4), 648-byte END+length form + 176-B inventory info records, off-mode identity contract (§12.1, linked instruction bytes); join completion lengths to operation identity in userspace only when the flag is on (no `AggKey` dimension, no `metadata_at_use` rewrite, corroboration slot for retained completions, U1 parking for rowless keys); publish closed v7 row keys with per-mode concise text, `-v` detail and a one-line off-mode hint; capture fixed-size provider/token/mechanism fields at return on CKR_OK (Task 7, 176-B records + schema section, default inventory and CBOM, independent of the flag).

## Global Constraints

- Never capture PINs/keys/payloads/env; `docs/privacy/allowlist-v1.md` byte-identical.
- Missing observations stay unknown with named reasons; refusals, loss and PARTIAL coverage reported honestly.
- No BPF change before the applicable amendment text passes owner/Opus privacy review + Codex re-review (§11 + R2 block for Tasks 1–4, §17.3 for Task 7 — each still PROPOSED until then).
- `metadata_at_use` stays established-only and frozen at Init receipt; no-backfill pins re-run green.
- Journal classification, the `[0,19,79,6]` census, the sole-complete 20, alias agreement, the v1 tail and its validator stay byte-identical (non-interference twins in Task 2).
- Length capture is opt-in (`--key-sizes`, off by default, §10.5) in extra journal-object programs loaded and linked only with the flag (§8.6): with the flag off, hot-path records, ring/journal load, the linked program set at hot endpoints, base-program bytes and classification are exactly today's (off-mode identity contract, §12.1; the only linked-set additions are the cold-only Task 7 inventory info programs). Base-program linked instruction streams stay byte-identical to the baseline for the lane's rebased base (keymeta lanes never re-hash; the integrator re-records the baseline when a non-keymeta lane changes the base programs, §8.5); journal and usage-entry cells in `tests/bpf-verifier-budgets.json` are still checked as a backstop and never re-pinned by keymeta lanes.
- Profile, trace and metrics never carry object facts; observed-profile v2/v3 untouched.
- Schema section versions: v6 = R2 + per-field source, v7 = inferred keys, Task 7 section = next free (suggest v8); older versions frozen and byte-stable.
- Concise CLI default; inferred facts parenthetical only where they add information; `-v`/JSON carry detail.
- Cargo only via `mise exec -- ./scripts/cargo.sh`; TMPDIR on disk, umask 022.
- Tests-first: RED run saved outside tracked files, then GREEN; every new check non-vacuous.

## Review Focus

- A length cell aliasing payload bytes must refuse via span guards, never publish a payload-derived class — pinned by disjointness twins in Task 2.
- A cell above the buffer (NSS/pkcs11-provider layout) must be accepted — pinned by the above-buffer twin in Task 2.
- A 2041-bit RSA key (256-byte signature) must show "RSA 2048 (from signature length)" with `size_class: 2048` + `modulus_bytes: 256`, never `rsa_2048` in `metadata_at_use` — pinned by the 2041 control in Task 3.
- A key used under two specific mechanism families must show `conflicting` with both sides, never first-wins — pinned by conflict twins in Task 3; `secret` beside any family and compatible §4.5 pairs never conflict.
- A query/too_small/terminal triple must yield exactly one completion — pinned by the over-estimate twin in Task 3.
- Inferred facts must never reach CBOM `related-crypto-material` established fields — pinned by a CBOM exclusion twin in Task 3.
- A provider with NULL `C_SignRecover` must still admit no-manifest key operations (no entry gating change) — pinned by an authority twin in Task 2.
- A provider returning sentinel serial/label/session/memory/clock/pad bytes must publish none of them anywhere — pinned by the Task 7 sentinel + CBOM twins; PIN-state bits and PIN lens publish exactly.
- A flag-off run must be indistinguishable from the no-length baseline on hot paths (base-form ENDs only, today's linked set at hot endpoints, byte-identical base-program linked instruction streams, baseline ring bytes/s) — pinned by the off-mode identity contract in Task 2; `--key-sizes` without `--key-operations` (and under P0) must refuse — pinned by CLI twins in Task 2/3.
