# p11scope v0.7.0

## [0.7.0] - 2026-11-13

v0.7.0 shows which application called the token, fixes system-wide
binding, and ships a container image.

What's new (one line each):

- App labels: `python3 [backup.py]`, `java [app.jar]` name the app behind the runtime.
- Launcher chain: callers show `from backup.sh` (one hop; full chain in verbose and JSON output).
- `inventory --system` now binds usage on large hosts (was: zero rows).
- Deferred admission refusals settle once the endpoint is admitted (was: up to 2 stayed refused).
- Mechanism names without `--manifest` when provider tables qualify by standard layout (observed live return, linked table, or scan-proved sole complete table).
- Late providers compete better for freed attach slots under churn instead of staying refused.
- Observer memory stays flat under process churn (was: grew toward ~1 GB/hour on a busy host).
- stdout/stderr keep working under sudo with tighter capabilities.
- Container copy-ups attribute both file versions, so calls on either side count.
- Tested against OpenSSL, p11-kit, pkcs11-tool and GnuTLS clients, plus Firefox and Chromium end to end.
- Container image `ghcr.io/mingulov/p11scope:0.7.0` for Docker and Kubernetes, with build-provenance attestations on the image and every release file.
- Exact totals when many threads share one provider (rows may stay partial, see known issues).
- Tested on Linux 7.4-rc2, plus the 6.6–7.3 matrix.
- Cost: overhead is visible, and it works well at 5,000 calls/s on a VM with limited resources.
- `run` hands your program back instead of killing it: a stopped run, a spent event budget or a capture error leaves the child running.
- Every run that collected data writes its report, even when refused, stopped or interrupted.
- Captures degrade honestly instead of showing empty views: a scan report where live capture is unavailable, partial results when stopped early.
- `inventory --event-log -` streams live events to stdout for container log collectors, with optional periodic totals.
- Docs pack: [troubleshooting](../troubleshooting.md), real first-run output, [why not just pkcs11-spy?](../overview.md#why-not-just-pkcs11-spy), [tested targets](../overview.md#tested-providers-and-applications).
- Attach slots: 2,112 per capture (was 512), retired slots are reused once final, oversized providers attach in part with a named gap, and counter modes plus the production journal ship at the wide profile.
- One-shot tools under `--system` are caught from their second run: providers at any path are learned from the kernel, listed with the program that loaded them, and attached for later runs (first use stays a named gap).
- `--pid` targets that exec mid-capture disclose the new program (`exec_to_exe`) beside the attach-time name.
- Browsers started after a background caller now get per-key tracking (first calls stay unattributed).
- Per-key tracking works without `/boot/config-*`: the running `/proc/config.gz` is read first.
- A stalled stderr no longer stalls the capture (diagnostics shed instead of blocking).
- Kernel-thread exits no longer count as lost processes; loader attaches retry past racing exits.
- Guest and cgroup captures classify stopped and refused work correctly.
- Per-key rows without `--manifest` once the scan seal seats (`--cgroup` attempts the seal too).
- Quiet Docker/`--cgroup` captures no longer report PARTIAL for publication-only post-ready work.
- Text output prints full provider paths with container origins in ASCII-only text.
- Mechanism names through verified p11-kit-proxy forwards (forwarded slot stays count-only).
- File learning covers shadowing mounts and file binds, skips automounts, bounds the mark pass.
- Stale manifests grant names only, never semantics.
- Faster discovery at scale: lazy raw-key index, by-ID pin lookup, cheaper bind and projection.
- Deep scan covers 1,024 user processes (was 256), one examination per library set, with a counted gap.
- No more file-descriptor wall (raised limit plus a held reserve) or dropped handles (wait and retry).
- Live discovery looks only at user processes, so kernel threads no longer cause "new processes pending" skips on busy hosts.
- System-wide runs no longer count p11scope's own short-lived self-check helper as a pending process.
