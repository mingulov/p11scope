# v0.8.0 Key Metadata Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship inferred key family, size class, and source-carrying creation facts on per-key rows, plus provider/token/mechanism info (Task 7).

**Architecture:** Port the R2 creation-template path with per-field source (v6); add S-cell/V-scalar length adapters on 7 new + length positions on 4 extended object descriptors (existing actions kept, none migrates) with a wire v2 tail; join completion lengths to operation identity in userspace (no `AggKey` dimension, no `metadata_at_use` rewrite); publish closed v7 row keys with concise text and `-v` detail; capture fixed-size provider/token/mechanism structs at return on CKR_OK (Task 7, own wire record + schema section).

**Tech Stack:** Rust (edition 2024, release toolchain `.release-rust-version`), existing object-capture adapters; no new crates, no new maps.

**Spec:** `docs/superpowers/specs/2026-11-14-v080-keymeta-design.md`
(round 5: per-ABI §17.1 layouts, Task 7 merge order (after Task 3,
Step 0 after Task 0, Task 6 after Task 7), K3 on the closed §10.2
shape (owner 07:52 override kept), Task 8 postponed to Later
(spec §18); schema version allocation is the integrator's —
Task 3 re-points if keyrows claims a version first).

## Global Constraints

- Never capture PINs/keys/payloads/env; `docs/privacy/allowlist-v1.md` byte-identical.
- Missing observations stay unknown with named reasons; refusals, loss and PARTIAL coverage reported honestly.
- No BPF change before the applicable amendment text passes owner/Opus privacy review + Codex re-review (§11 for Tasks 1–4, §17.3 for Task 7 — each still PROPOSED until then).
- `metadata_at_use` stays established-only and frozen at Init receipt; no-backfill pins re-run green.
- Profile, trace and metrics never carry object facts; observed-profile v2/v3 untouched.
- Schema section versions: v6 = R2 + per-field source, v7 = inferred keys, Task 7 section = next free (suggest v8); older versions frozen and byte-stable.
- Concise CLI default; inferred facts parenthetical only where they add information; `-v`/JSON carry detail.
- Cargo only via `mise exec -- ./scripts/cargo.sh`; TMPDIR on disk, umask 022.
- Tests-first: RED run saved outside tracked files, then GREEN; every new check non-vacuous.

## Review Focus

- A length cell aliasing payload bytes must refuse via span guards, never publish a payload-derived class — pinned by overlap/alias twins in Task 2.
- A 2041-bit RSA key (256-byte signature) must show "RSA 2048 (from signature length)" with `size_class: 2048` + `modulus_bytes: 256`, never `rsa_2048` in `metadata_at_use` — pinned by the 2041 control in Task 3.
- A key used under two mechanism families must show `conflicting` with both sides, never first-wins — pinned by conflict twins in Task 3.
- Inferred facts must never reach CBOM `related-crypto-material` established fields — pinned by a CBOM exclusion twin in Task 3.
- A provider with NULL `C_SignRecover` must still admit no-manifest key operations (length entries per-entry optional) — pinned by an authority twin in Task 2.
- A provider returning sentinel serial/label/PIN/clock bytes must publish none of them anywhere — pinned by the Task 7 sentinel + CBOM twins.
