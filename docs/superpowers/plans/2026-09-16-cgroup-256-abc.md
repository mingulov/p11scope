# Cgroup-256 fixes A–C Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix multi-process discovery so `profile --cgroup /` finds providers: decode each unique table once, make the 256 cap measured/configurable/documented with reusable view IDs, and scan all pids in two phases.

**Architecture:** Budget-owned admission stays the choke point; an Engine-side decode cache keyed by table identity removes repeat decodes; the pid cap becomes an Engine field fed by a CLI flag; view-ID allocation gains a free-list fed by existing view-removal sites; the initial scan splits into a maps-only sweep plus deep-scan of unique candidates.

**Tech Stack:** Rust 1.88 (`cargo +1.88`), clap-free hand-rolled CLI (`src/cli.rs`), existing `engine_tests.rs` fixtures.

**Spec:** `docs/notes/2026-09-16-cgroup-256-trace-everything.md` — the plan argues from it; executors read both. The kill chain (every GNOME proc re-decoding libp11-kit burns the shared 512-candidate budget) and the measured numbers (15.5s/0 probes cgroup vs 172ms/272 probes single-pid) are the acceptance authority.
