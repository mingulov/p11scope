# Cgroup-256 Fix A2 + cap follow-through Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make multi-process captures survive scale: dedup file reads by identity so the 512 MB I/O budget stops dying on re-reads, make the view-ID allocator follow the configured cap, and turn ID exhaustion from fatal into published PARTIAL evidence.

**Architecture:** A per-capture inspected-file cache owned by `CaptureWorkBudget` (no signature churn — the budget already flows everywhere); the allocator's ceiling reads `Engine.max_scan_pids` instead of the const; the initial-scan `?` on allocation becomes skip-and-break.

**Tech Stack:** Rust 1.88 (`cargo +1.88`), existing `engine_tests.rs` / identity / scan test fixtures.

**Spec:** `docs/notes/2026-09-16-cgroup-256-io-ceiling-followup.md` — the plan argues from it; executors read both. Strace-measured acceptance authority: one root capture re-reads ~3.6 GB of identical file bytes (whole `.so` files per view); post-fix repeats must read ~0. Single-variable proof exists (16 GB ceiling flip: 0 → 3 providers).
