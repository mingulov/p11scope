# v0.1 Corrective Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Use superpowers:test-driven-development for every behavior change and superpowers:verification-before-completion before any completion claim.

**Goal:** Fix all validated v0.1 review findings at their shared causes, support every published function-table ABI from PKCS #11 2.00 through 3.2, and make silent evidence loss mechanically impossible to report as complete.

**Architecture:** Keep PKCS #11 FFI facts in the existing `pkcs11-module` and `pkcs11-proxy-ng-types` crates. Discovery snapshots provider memory through `/proc/self/mem`. One generated per-slot descriptor drives both BPF argument capture and the userspace operation state machine. Aggregate BPF maps remain count authority; every lossy or failed capture path has an independent evidence counter that forces `PARTIAL`.

**Tech stack:** Rust 1.88, edition 2024 for userspace, Aya 0.14.0, aya-ebpf 0.2.1, C provider fixtures, glibc and musl Linux containers. Add no dependency unless an existing dependency or the standard library cannot do the job.

**Authoritative design:** `docs/superpowers/specs/2026-08-12-v0.1-corrective-release-design.md`, as amended by `docs/superpowers/specs/2026-08-13-safe-and-unvalidated-metadata-design.md` and Tasks 4–7 of `docs/superpowers/plans/2026-08-13-manifest-provenance.md`.

**Execution warning (2026-08-13):** Do not execute this plan standalone. Its
manifest-v3, profile-v1.3/metrics-v1, raw-pointer decoder, and first-pass
provenance clauses are historical intermediate steps. The two amendments above
supersede them with manifest v4, profile v1.4/metrics v1.1, a safe default plus
explicit diagnostic feature, exact-inode closure stabilization, and ordered
lease-supervisor teardown.
