# Lane 14 canary surface crosswalk

This is the literal Lane 14 retained-file crosswalk. It is based on
`scripts/verify-canaries.sh`, `scripts/dump-owned-bpf-maps.py`,
`scripts/check-bpf-map-defs.py`, and `docs/privacy/allowlist-v1.md`.
Every row names one retained file; no row authorizes a glob, basename
selection, directory-order selection, or a derived substitute.

The `resource associations` column uses slash-separated planning tokens for
readability. Each semicolon-separated token binds one runtime `ResourceDecl`
label by the exact normalization ASCII-lowercase(token) with every `/` replaced
by `.`; no other transformation is permitted. Thus
`map/default-safe-profile/START` binds `map.default-safe-profile.start`, and all
normalized labels satisfy the contract label grammar.

Per-lane rows use this exact order:

`default-safe-profile`, `default-safe-trace`,
`feature-safe-profile`, `feature-safe-trace`,
`feature-unsafe-profile`, `feature-unsafe-trace`,
`aggregate-only-metrics`, `default-safe-start`,
`feature-safe-start`, `feature-unsafe-fault`.

Safe lanes own the 15-map inventory: 13 ordinary maps plus ring maps
`EVENTS` and `DISCOVERY`. Unsafe lanes add ordinary maps
`ATTR_BOOL_BITS` and `TEMPLATE_TAIL`. The two ring raw files are retained
only for the first seven matrix lanes, exactly as the canary driver reads them
through its mmap oracle. START lanes retain the ordinary dumps needed by their
START/fault oracles; `mapdump_START_live.json` is the one separately
published START copy.

## Recomputed category table

| category | exact composition | count |
| --- | --- | ---: |
| outputs | 7 nontrace JSON plus 3 trace outputs | 10 |
| observer logs | one per lane | 10 |
| workload logs | one per lane | 10 |
| map manifests | one per lane | 10 |
| ordinary map dumps | 7 safe lanes x 13 plus 3 unsafe lanes x 15 | 136 |
| ring raw | 7 matrix lanes x EVENTS and DISCOVERY | 14 |
| START_live | one published START copy | 1 |
| discovery manifests | matrix and privacy | 2 |
| positive control | one intentionally planted PIN sentinel | 1 |
| **total** | **10 + 10 + 10 + 10 + 136 + 14 + 1 + 2 + 1** | **194** |

The exact privacy-target invariant is **191**: all 194 rows except the two
discovery manifests (input-only) and the one positive control
(positive-control). Thus **privacy targets = 194 - 2 - 1 = 191**. The positive
control must detect the forbidden sentinel and is never promotable to privacy
evidence.
